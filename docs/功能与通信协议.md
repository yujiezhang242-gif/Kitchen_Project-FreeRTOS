# 功能与通信协议

## 1. 业务行为

自动模式：30°C 进入高温，27°C 恢复；湿度 70%RH 开通风口，60%RH 恢复；暗阈值 raw=2800 点灯，raw=2400 熄灯。回差带内保留状态。默认温湿度/光照只是演示阈值，需按实际环境标定。

高温或数据失效发出告警。消音默认 60 秒；确认不清除故障，新出现的高温或故障来源会取消消音。通道分别在数据到达 5 秒寿命或校验/范围错误时失效：温湿度失效请求通风，光照失效保持原照明；健康通道继续参与控制。

手动模式支持灯和通风口控制，最长 300 秒，随后恢复自动。高温和温湿度故障覆盖手动关闭通风口的请求；光照故障不单独强制通风。手动模式不清除故障。配置只保存自动阈值与超时，手动模式与消音状态不持久化。

## 2. 任务与数据所有权（当前代码）

| 任务 | 优先级 | 栈/32位字 | 调度方式 |
|---|---:|---:|---|
| Health | 6 | 192 | 每 500ms 检查，满足期限和栈余量才喂狗 |
| Control | 5 | 384 | 每 20ms，最多处理 4 条串口命令、1 个按键事件 |
| Sensor | 4 | 256 | 每 100ms，DHT 每 2 秒；ADC 32 点 DMA 采样求均值 |
| Comm | 3 | 448 | 每 5ms，最多处理 256 字节，再发送一条应答 |
| UI/Input | 2 | 384 | 20ms 消抖，200ms 更新文本；独占 OLED |
| Storage | 1 | 256 | 最长 100ms 等待请求，独占参数 Flash 写入 |

用户任务栈合计 7680B，idle 栈、TCB 和队列也全部静态提供；禁用动态分配，不再编译 heap_4。创建均检查结果。链接容量和板上栈水位分别检查，详情见工程化v2.md。

采样和显示分别使用长度 1 的覆盖邮箱，避免消费者慢时阻塞生产者。命令/应答队列各长 4，满时拒绝或计数；按键独立队列避免与串口序号冲突。Control 独占 runtime，Storage 通过配置副本处理保存，完成后按 revision 判断能否清除 dirty，避免保存旧参数时把新修改误标成已保存。

DMA/USART ISR 只收集字节、清标志和计数，不调用 RTOS API，不刷屏，不延时。DMA/USART 中断优先级数值为 5，DHT 边沿解码 EXTI 数值为 1，分组为 4；EXTI 同样不调用 RTOS API。业务决定在任务里完成。Health 有 3 秒启动宽限，工作任务循环超过 1.5 秒未完成视为超时；IWDG 超时约 5 秒，受内部低速时钟实际频率影响。

## 3. 帧定义

```text
AA 55 | version:u8=1 | command:u8 | seq:u16 | length:u16 | payload | crc:u16
```

所有多字节数值小端，载荷最多 128B，总帧最多 138B。CRC-16/MODBUS，初值 0xFFFF、反射多项式 0xA001，覆盖 version 到 payload，低字节先发。此自定义帧不是 Modbus RTU。

接收器跨调用保存半包，200ms 未收到后续字节则丢弃半包；长度超限、版本错误、CRC 错误后重新搜头。没有身份验证，适用于本地串口调试，不应直接暴露到公共网络。

应答 command=请求 command OR 0x80，seq 原样返回，payload 第一字节为结果：0 OK、1 长度错误、2 数值错误、3 BUSY、4 不支持、5 序号冲突、6 存储错误。

## 4. 命令

| 编号 | 命令 | 请求 payload | 应答除结果字节外 |
|---:|---|---|---|
| 1 | STATUS | 空 | uptime u32、temp i16、humid u16、light u16、flags u16、manual u8、dirty u8、sample_age u32、revision u32、light_age u32、valid_mask u8 |
| 2 | GET_CONFIG | 空 | 20B 配置 |
| 3 | SET_CONFIG | 20B 配置 | 空；成功后仅改变运行配置，dirty=true |
| 4 | MANUAL | lamp u8、vent u8、duration_ms u32 | 空；duration=0 表示回自动；其他为 1..300000 |
| 5 | ACK | 空 | 空 |
| 6 | LOG | 最新日志索引 u8，0 为最新 | count u8、timestamp u32、event u16、value u16 |
| 7 | SAVE | 空 | 空；固件实际保存完后才应答，忙/限频时返回 BUSY |
| 8 | DIAG | 空 | 见下方；业务模拟器未实现该板级命令 |

STATUS flags：bit0 灯、bit1 通风请求、bit2 蜂鸣器、bit3 高温、bit4 任一传感器故障、bit5 温湿度故障、bit6 光照故障。温度和湿度单位为 0.1°C、0.1%RH；light 是 ADC 原始值。sample_age/light_age 分别是温湿度/光照最后成功采样的年龄；valid_mask bit0/bit1 表示最近一次温湿度/光照读取成功。有效位不代替年龄检查，最终故障结果以 flags 为准。应答载荷含结果共 28B。

配置载荷依次为：temp_on i16、temp_off i16、humid_on u16、humid_off u16、dark_on u16、dark_off u16、stale_ms u32、mute_ms u32。必须满足 on>off；温度阈值在 -400..1250，湿度 0..1000，ADC 0..4095，两个时间区间在 1..0x7FFFFFFF。宽范围用于控制器通用校验，不代表 DHT11 有此量程。

DIAG 结果字节后为 12 个 u32：复位标志、当前空闲堆、历史最小空闲堆、传感器错误、RX 软件队列丢字节、UART 错误、命令队列丢弃、应答丢弃、TX 错误、显示错误、CRC 错误、半包超时；随后 5 个 u16：Sensor/Control/UI/Comm/Storage 的栈最小剩余字数。原始复位标志按 STM32 RCC_CSR 定义解析。v2 的两个堆字段为 0，表示禁用动态堆；UART 错误也包含检测到的 DMA 边界积压。

重复设置完全相同的配置不增加 revision，也不触发 dirty。SET_CONFIG、MANUAL、ACK 缓存最近 4 条命令，10 秒内相同 seq 与相同内容返回缓存应答，不重新执行；相同 seq 但不同内容报冲突。只支持一个串口客户端，重连应使用新序号。SAVE 在未修改时直接返回 OK，实际写入采用独立忙状态和 10 秒限频，未提供跨重启命令去重；超时后先读配置状态。STATUS/GET_CONFIG 每次读取最新状态。

## 5. 参数记录与日志

每个参数区使用独立 1KiB 擦除页，每页追加 25 条，写满才换页；每条记录 40B：magic(4)、schema(2)、length(2)、generation(4)、保留(4)、配置(20)、CRC(2)、commit(2)。先写和回读前 38B，再写提交标记 0x5AA5；启动仅接受格式、CRC、提交标记和参数范围都正确的记录。扫描两页全部槽位选择更新的 generation，比较考虑回绕；撕裂记录不复用。完整换页流程见工程化v2.md。

日志为 16 项 RAM 环形记录，覆盖最旧项并统计覆盖次数。event=1 输出/告警位变化，2 参数修改，3 模式切换，4 确认告警，5 启动配置来源（1 有效记录/0 默认值），6 保存结果（1 成功/0 失败）。日志查询期间若有新事件，索引可能变化，不是事务性快照。

## 6. Python 工具示例

下例把 COM5 替换为 Windows 实际端口；Mac 使用 `/dev/cu.*`。

```sh
python tools/kitchen_cli.py --port COM5 status
python tools/kitchen_cli.py --port COM5 config
python tools/kitchen_cli.py --port COM5 set temp_on=300 temp_off=270
python tools/kitchen_cli.py --port COM5 save
python tools/kitchen_cli.py --port COM5 manual --lamp 1 --vent 1 --seconds 30
python tools/kitchen_cli.py --port COM5 auto
python tools/kitchen_cli.py --port COM5 ack
python tools/kitchen_cli.py --port COM5 logs
python tools/kitchen_cli.py --port COM5 diag
python tools/kitchen_cli.py --port COM5 monitor --csv run.csv --interval 1
```

`set` 不会自动保存；读回配置后再显式 save。上位机逐条请求并等待应答，避免 Flash 擦写窗口内继续发流量。

新增命令 9 TIMING、10 CRASH、11 CLEAR_CRASH 的格式与暖复位保留区见 [工程化v2](工程化v2.md)。
