# 工程化 v2

## 1. 构建和资源门禁

当前提供两条路径：Keil ARMCC5 使用原 RVDS Cortex-M3 移植层；GNU 使用项目维护的语法适配版本、GNU 启动文件与链接脚本。GNU 不是下载得到的官方 GCC port，也未经过实物上下文切换验收，不能将其与上游同名实现等同。

原 CMSIS V1.30 在新 GCC 下会把 STREXB/STREXH 的输出与输入分配到相同寄存器，汇编器报错。已为 GNU 的三个 STREX 包装增加 early-clobber 与 memory 约束，ARMCC 分支不改。新 GNU 工程使用 C99、优化 Os、函数/数据 section GC、Wall/Wextra/Werror。

自动检查：

- ELF 必须为 ARM ELF32 little endian，复位入口与向量一致，初始 MSP 为 0x20005000。
- 所有 Flash 加载段截止 0x0800F800，禁止覆盖两页参数日志。
- RAM 静态对象不能侵占预留的 1KiB MSP 空间。
- 必须存在静态任务/队列和目标中断处理符号，不允许 malloc/pvPortMalloc/snprintf 等符号进入映像。
- release 打包核对构建时源码指纹和 ELF/HEX/BIN/map 哈希，源码或产物变化后必须重新检查。

GNU 实测容量见 release/kitchen.resources.json。剩余 RAM 不是实际空闲任务栈：各工作任务栈已包含在静态区域中，诊断里的水位仍需上板测量。

## 2. 静态分配

configSUPPORT_STATIC_ALLOCATION=1，configSUPPORT_DYNAMIC_ALLOCATION=0，不编译 heap_4。每个任务有确定的 StaticTask_t 和 StackType_t 数组，七个队列有确定的控制块和载荷缓冲；idle 通过 vApplicationGetIdleTaskMemory 提供内存。保留创建结果检查和栈溢出钩子。

显示不再依赖 snprintf。text_format 仅支持实际使用的整数/文本格式，限制输出大小，无浮点、动态分配和 stdio 全局状态。协议原 DIAG 的 heap_free/heap_min 字段保留为 0，表示禁用动态堆，不表示内存耗尽；应结合 timing 的 build_abi=2 与栈水位判断。

## 3. Flash 追加日志

每页 1KiB，40B 一条，共 25 条，尾部 24B 不用。记录格式兼容上一版的 40B 单记录布局；启动扫描两页全部槽位，选择最新 generation 的已提交有效配置。

正常保存追加至当前页的下一个槽，不擦除。记录内容写入并回读后，最后写 commit。写满后擦除另一页并写入第一条；当前有效页始终保留，直到新页有完整记录。CRC/提交无效的非空槽不复用。写失败后重新扫描，避免重写已编程的位或重复使用未知提交状态。读取错误时禁止写入/擦除，读取恢复后再重新扫描。

测试包含追加和换页每个半字位置的失败、CRC 回退、失败重试、generation UINT32_MAX→0、读取错误拒写。空白介质从零开始连续 100 次写入发生 3 次擦页。这个数字只描述算法测试，不代表已测得实物寿命或实际写入耗时。

内部 Flash 操作仍会阻塞取指。追加降低擦除频率，不能消除编程和擦页时延；保存时上位机采用请求/应答，实际最坏时延需要测量。

## 4. 时间与执行预算

DWT CYCCNT 自由运行，按差值累计墙钟毫秒；频率使用 SystemCoreClock。72MHz 下约 59.6 秒回绕，调用者必须在一个回绕内读取；Health 每 500ms 读取，IWDG 约 5 秒，因此正常设计不会跨越整圈。长时间调试暂停不计为真实运行时间，仍需板上检查 DWT 行为。

Control 用 vTaskDelayUntil 维持 20ms 的 RTOS 调度周期。DWT 统计启动间隔、一次执行时长，包含抢占/取指等待；执行预算 5ms，间隔超过 25ms 计 late。不会声称已达成这些预算，只有板上数据能证明。

命令 9（TIMING）：请求为空，应答结果之后为六个 u32：cycles、max_interval_us、max_execution_us、late_intervals、overruns、build_abi=2。原 CMD_DIAG 保持兼容。

## 5. 故障记录

RAM 0x20000000..0x200000FF 为独立保留区；普通 data/bss 从 0x20000100 开始。GNU 为 NOLOAD，Keil scatter 为 UNINIT；启动清零不会覆盖此区域。记录 88B：magic/version/sequence、reason、uptime、EXC_RETURN、异常栈 r0/r1/r2/r3/r12/LR/PC/xPSR、CFSR/HFSR/MMFAR/BFAR、MSP/PSP、任务掩码及 CRC32。

HardFault 入口依据 EXC_RETURN 选择 MSP/PSP，检查异常栈地址后才读取 8 个字；诊断函数不分配内存、不打印、不擦写 Flash。Health 发现工作任务超时后保留掩码，停止喂狗。普通 panic 也写入原因。记录先废弃 magic，写内容和 CRC，最后提交 magic，半写记录不会当作有效记录。

命令 10（CRASH）：空请求，应答结果后 valid:u8 + record:88B。命令 11（CLEAR_CRASH）：空请求，清记录。只能期望暖复位保留，ST-Link 下载、启动器或电源变化可能清除 SRAM；断电无保留保证。该实现不是可恢复异常系统，也不能保证栈/总线严重损坏时诊断仍完成。

## 6. 通信缺口

接收 DMA 缓冲为 256B，软件队列 512B。半满/全满标志同时积压说明无法可靠确定已完成窗口，丢弃该窗口并增加错误 epoch；软件队列满时废弃排队数据并计丢弃；USART ORE/FE/NE 同样废弃受影响数据。Comm 在每个字节前检查 epoch，重置协议半包。

这使缺口有明确处理，不把丢字节后数据继续当成完整流；不能恢复丢失命令，也不能证明持续超带宽输入可无损。查询/保存命令仍以有界请求/应答为正常操作方式。

## 7. 接下来必须在板上验证

GNU 与 Keil 均需分别验证启动、任务上下文切换、ADC/UART DMA、DHT 中断时序、OLED 与 PWM。特别记录：DWT 与外部时间的偏差、保存/换页期间最大控制间隔、DMA 缺口计数、真实断电后的参数选择、看门狗复位后故障记录是否保留，以及任务栈水位。没有这些数据，不能称为工业级或量产固件。
