# 上板与虚拟机操作

## 1. 开发组合

用户已确认有套件内 STM32、OLED、DHT11、ST-Link，并在 Mac 虚拟机运行 Keil。本版本默认 MCU 为 STM32F103C8T6、外部晶振 8MHz、系统时钟 72MHz；显示驱动为 128×64、I2C 地址 0x3C、SSD1306 兼容 OLED。套件不同批次可能使用其他 OLED 控制器，若显示错位/不亮，应根据模块标识修改驱动，不要据此判断 MCU 没运行。

工程使用原项目相同的 ARM Compiler 5 系列工具链与 RVDS Cortex-M3 移植层。若虚拟机仅安装 ARM Compiler 6，本工程不能只切换编译器后直接使用；应安装匹配的 ARMCC5，或完整迁移移植层、启动文件与重定向后再验证。

## 2. 默认接线

以 `firmware/board/board_config.h` 和 `board.c` 为准。

| 模块 | MCU 引脚 | 连接说明 |
|---|---|---|
| OLED SCL/SDA | PB6 / PB7 | I2C，确认模块上拉；本驱动使用开漏软件 I2C |
| DHT11 DATA | PB8 | 数据线上拉至 3.3V；若模块自带上拉需确认其电压 |
| 光照 ADC | PA1 | 输入 0..3.3V；使用模拟 AO，数字 DO 不适合模拟亮度测量 |
| 舵机信号 | PB0 / TIM3_CH3 | 默认 50Hz，1000µs/2000µs 两档，机械位置需实测 |
| LED | PC13 | 低电平点亮；若核心板没有 LED 可外接限流 LED |
| 有源蜂鸣器控制 | PB15 | 默认高电平有效，使用匹配驱动模块 |
| 按键 1 / 2 | PB1 / PB12 | 按下接 GND；内部上拉；确认告警 / 切换页面 |
| USART1 TX/RX | PA9 / PA10 | 接 USB 转串口 RX/TX，115200 8N1，3.3V 逻辑 |
| 调试 | PA13 / PA14 | ST-Link SWDIO/SWCLK，另接 GND、目标电压参考 |

模块共地。舵机使用合适的独立供电并与 MCU 共地；先不接机械负载，确认脉宽和位置后再装联动结构。ADC 只能接范围内的电压。蜂鸣器/负载模块的驱动能力和有效电平以实物为准。

如果套件光敏模块只有数字 DO，可用独立光敏电阻与固定电阻做分压：3.3V → 固定电阻（例如 10kΩ）→ PA1 → 光敏电阻 → GND。此接法暗时 ADC 增大，对应当前算法；若反接则需要反转规则。未标定前界面和协议只显示 raw ADC，不显示 lux。

暂不需要采购 Wi-Fi、SD 卡或新主控。先把已有模块的本地版跑通；若套件缺少上述任一模块，可先留空，通过串口和故障提示验证其他部分。

## 3. Mac 虚拟机与 USB

1. 把整个 `Kitchen_RTOS_Pro` 目录复制到虚拟机本地磁盘，建议路径 `C:\Projects\Kitchen_RTOS_Pro`。保留目录结构，不只复制 uvprojx。
2. 在虚拟机 USB 设置中把 ST-Link 分配给 Windows，安装对应驱动。设备管理器应能识别 ST-Link。
3. 若 Python 工具在 Mac 运行，把 USB 转串口留给 Mac；若在 Windows 运行，把它分配给 Windows 并使用 COM 端口。一台 USB 设备同一时刻由一侧系统占用。
4. 在 Keil 打开 `firmware\Kitchen_RTOS_Pro.uvprojx`，确认 ARM Compiler 5 与 STM32F1 设备支持包可用。
5. Target 为 STM32F103C8；调试器选 ST-Link / SWD。项目使用 MicroLIB，C99，ARM_CM3 的 RVDS port。不要混用 Cortex-M4 移植文件。
6. 完整 Rebuild，保存 build log 和 map。必须确认无链接错误、程序加载区域不超过 `0x0800F800`、RAM 使用不超过 20KiB。Keil 免费版本的代码容量限制也可能影响构建，实际以本机许可证与链接结果为准。
7. 工程链接文件是 `kitchen.sct`：应用 0x08000000..0x0800F7FF；参数 A/B 分别从 0x0800F800、0x0800FC00 开始，各 1KiB。不要扩大程序区域占用参数页。
8. 首次下载先断开舵机信号与负载。烧录后用串口 `status` 确认程序，再逐个连接传感器、显示和执行器。

重新下载程序时若执行全片擦除，参数也会清空，这是下载器行为；日常参数持久化验收应仅通过断电重启测试。需要跨固件下载保留参数时，明确选择按程序区域擦除，并核对下载器日志。

## 4. 首次验证顺序

1. **无传感器启动**：串口可查询；状态为 sensor_fault；程序没有因为读取失败卡死。
2. **OLED**：出现 KITCHEN RTOS，按键 2 切换诊断页。显示无响应不应阻断串口和控制。
3. **DHT11**：正常数据后故障恢复。每 2 秒采集温湿度，光照每 100ms 采集；温度/湿度单位均以实际传感器精度为准。
4. **光照**：遮挡传感器观察 raw 变化，确定方向后调整 dark_on/dark_off；回差带内保持前一状态。
5. **联动**：先看状态里的 ventilation/lamp/buzzer，再接舵机并验证 PWM。ventilation 表示“开合通风口请求”，当前没有真实风机与位置反馈。
6. **按键**：按键 1 消音，故障仍存在；到时或新故障到来重新鸣叫。按键 2 只换页。
7. **配置**：串口改阈值后显示 UNSAVED，显式 save 成功后显示 SAVED；断电重启后读取配置。
8. **诊断**：观察 stack_free_words、timing、CRC 错误和串口丢弃计数；v2 禁用动态堆，heap 字段为 0。任何栈余量不足都要先修复，再进行长时间运行。

## 5. 当前板级限制

- DHT11 使用 PB8 双边沿 EXTI 中断与 TIM4 的 1MHz 时间戳。EXTI 优先级数值为 1，不调用 RTOS API，可在内核 BASEPRI 临界区期间响应。它仍是软件时间戳，不是硬件输入捕获；Flash 取指暂停或更高优先级异常可能影响采样。校验与接收时限拒绝坏帧，实物成功率待测。
- 温湿度与光照分别保存有效位和成功时间，独立判定超时。温湿度故障请求通风，光照故障保持照明，另一健康通道继续控制。两类故障都能告警，新出现的来源会取消消音。
- 内部 Flash 擦写会让 CPU 取指暂停，低优先级存储任务不能消除此影响。SAVE 期间上位机应等应答后再发下一条指令；不保证此期间 UART 持续洪泛不丢字节，也不保证 20ms 控制周期。
- UART RX DMA 缓冲 256B，在 115200 8N1 满速下约 22ms 回绕一次。HT/TC/IDLE 中断需要及时服务；如果被屏蔽跨越整圈，硬件覆盖可能无法由软件准确计数。该约束需要在负载测试中验证。
- 事件日志当前在 RAM，重启后不保留；参数保存到内部 Flash。
- Health 检查的是任务完成循环的时间和栈余量，未检测执行器物理到位；v2 已增加保留 RAM 的 HardFault 记录，但暖复位保留与异常入口仍需实物验证，断电不保证保留。

## GNU 完整构建路径

v2 已在 Mac 用 Arm GNU 12.3.Rel1 完整编译并生成 HEX/BIN；可先用此构建产物上板。Keil 仍可打开原工程，当前 Keil scatter 额外保留 RAM 最低 256B 的 RETENTION 区，不要改回普通清零区域。构建命令、容量报告与限制见 [工程化v2](工程化v2.md)。
